# Learning Space 设计与信息架构方案

## 1. 背景

当前 tomz.io 的内容体系主要围绕 Docs / Blogs 构建。

这套结构适合：

- 单篇文章
- 项目文档
- 独立说明页
- 按分类浏览的内容集合

但「一起学智能体」「读经札记」这类内容不是普通文章集合。

它们会持续增长，有明确的先后关系、阶段、上下文和长期积累。用户真正需要感知的不是“这里有多少篇文章”，而是：

> 这是一条正在继续走的路。

因此，本次改造不再把它们简单塞进 Blog / Docs，也不把它们包装成传统课程平台，而是建立独立的「研习」内容形态。

---

## 2. 核心定位

「研习」是 tomz.io 中承载长期学习路径、连续阅读记录与实践过程的一级内容空间。

它的基本模型是：

```text
主题
  ↓
学习路径
  ↓
章节 / 阶段
  ↓
札记 / 实践记录
  ↓
持续生长
```

当前首批主题：

- 一起学智能体
- 读经札记

未来可以自然扩展到：

- 设计研究
- 产品研究
- 某个长期专题

但首版不为了“以后可能有很多主题”提前制造复杂框架。

---

## 3. 与现有「书架」的关系

当前主站已经存在 `/books` 与顶栏「书架」入口，但现阶段内容很轻，主要用于表达阅读记录的概念。

本次改造后，不继续同时维护「书架」与「研习」两个相邻一级入口。

### 决策

- 顶栏「书架」改为「研习」
- 正式入口使用 `/learning`
- `/books` 作为兼容旧入口保留跳转
- 原有关于书架的内容可以并入研习说明，不继续扩展成另一套内容系统

原因：

「书架」更适合描述“收藏了哪些书”，而当前真正需要承载的是连续学习、阅读和实践过程。

「研习」覆盖范围更准确，也能同时容纳智能体学习与读经札记。

---

## 4. 产品原则

### 4.1 不是课程平台

不要出现典型 LMS / 在线课堂感：

- 不做课程购买
- 不做打卡体系
- 不做完成率 KPI
- 不做“第 1 课 / 第 2 课”式强制教学包装
- 不做类似后台 Dashboard 的模块卡片堆积

页面应该让人感受到“长期阅读与思考正在发生”，而不是“进入一套课程系统”。

### 4.2 不是知识库目录

不要退化成 Docs 左侧树状目录。

研习首页需要表达：

- 当前在学什么
- 最近走到哪里
- 最近新增了什么
- 这条路径为什么值得继续

目录只是进入内容的手段，不是首页主体。

### 4.3 保留个人轨迹

研习不是标准教材，而是 Tomz 的实际学习过程。

允许存在：

- 理解变化
- 阶段性结论
- 未解决问题
- 与 Mira 的讨论
- 实践后的修正

这些“过程感”是内容价值的一部分，不需要被清洗成一本标准教科书。

### 4.4 继承 tomz.io，而不是另造一套产品

研习页必须沿用主站已有视觉语言：

- 现有字体变量
- 现有颜色 token
- 现有页面宽度与留白系统
- 现有亮 / 暗主题
- 现有 Claude / Apple / Supabase 主题能力
- 现有导航与 Footer

禁止为了“书架感”单独造一个完全不同的 UI 系统。

---

## 5. 首页信息架构

首版 `/learning` 不采用“多个同权课程卡片”的 Dashboard 结构。

更接近：

> 两本正在继续写的活书 / 两条正在继续走的路径。

首页结构建议：

```text
研习
不是课程目录，而是一些仍在继续的学习、阅读和实践。

────────────────────

一起学智能体
AI / AGENT

以实际产品与工程问题理解 Agent、Tool Calling、MCP 等概念。

当前进度
08 · <当前章节标题>

最近一篇
<最近文章标题>

12 篇札记 · 3 次实践

[继续研习 →]

────────────────────

读经札记
READING / BIBLE

按实际阅读顺序记录经文背景、理解过程与个人思考。

当前读到
诗篇 · 06

最近一篇
当神似乎沉默的时候

诗篇 1—6 · 6 篇札记

[继续阅读 →]
```

### 首页应该强调

- 大标题
- 最近进度
- 最近内容
- 内容数量 / 范围
- 轻量路径感

### 首页不应该强调

- 三个标签式章节
- 大面积功能 icon
- 多个按钮
- 课程卡片 hover 特效
- 复杂进度条
- SaaS Dashboard 指标感

---

## 6. 视觉方向

### 6.1 整体气质

关键词：

- 阅读感
- 长期感
- 安静
- 有一点书页 / 索引 / 目录气质
- 仍然属于 tomz.io

不是：

- 在线课堂
- 知识付费首页
- Notion 模板市场
- AI SaaS Dashboard

### 6.2 可以使用的视觉隐喻

可以轻量使用：

- 页码
- 章节编号
- 书脊式纵向小标签
- 索引线
- 轻分隔线
- 当前阅读位置

这些只是视觉暗示，不要做成拟物书架。

### 6.3 图标

Lucide 可以继续使用，但图标只承担辅助识别，不做主要视觉中心。

例如：

- 智能体：Brain / Network / Bot 类图标
- 读经：BookOpen 优先于宗教符号作为主视觉

避免两个 30px 大 icon + 大圆角卡片形成“功能入口”感。

---

## 7. 内容模型

首版不急着引入数据库。

继续使用 Markdown + frontmatter，由现有 MiraDocs adapter / 静态生成链读取。

建议新增逻辑目录：

```text
src/pages/learning/
  agent/
  bible/
```

内容仍然是 Markdown，只增加研习需要的语义字段。

建议字段：

```yaml
title: MCP 为什么不是插件系统
description: ...
learning: agent
chapter: MCP
order: 8
status: published
date: 2026-08-xx
author:
  - tomz
  - mira
```

读经示例：

```yaml
title: 当神似乎沉默的时候
learning: bible
book: 诗篇
chapter: 6
order: 6
status: published
```

### 原则

- 内容事实来自 Markdown，不在 React 组件里手写进度
- 首页“当前进度”“最近一篇”“数量”均从内容自动计算
- 不维护两份相同数据

---

## 8. 主题详情页

建议路由：

```text
/learning
/learning/agent
/learning/bible
```

具体文章继续保留稳定 URL，可根据迁移成本决定是否移动历史文章路径。

主题详情页包含：

1. 主题简介
2. 当前进度
3. 最近更新
4. 按章节 / 阅读顺序组织的内容列表
5. 必要时展示关联实践或项目

不需要一开始就实现：

- 学习统计
- 用户账号
- 阅读打卡
- 收藏
- 完成状态同步

---

## 9. 与现有博客的关系

研习内容依然可以是一篇完整文章，但“研习”承担的是另一种聚合关系。

同一篇内容可以：

- 在 Blog 的时间流中出现
- 同时属于某条研习路径

因此，不要求为了研习强行复制 Markdown。

长期目标是：

```text
一份内容
  ├─ 时间维度 → Blog
  └─ 学习维度 → Learning
```

这样既保留个人站“最近写了什么”的时间流，也保留“这条路径走到哪里”的专题流。

## 10. 第一阶段施工范围

第一阶段只做能证明信息架构成立的最小闭环：

- [ ] 将顶栏「书架」改为「研习」
- [ ] 增加 `/learning`
- [ ] `/books` 兼容跳转到 `/learning`
- [ ] 首屏展示「一起学智能体」「读经札记」两条路径
- [ ] 页面数据不再硬编码进度，优先从现有内容推导
- [ ] 建立 `/learning/agent`、`/learning/bible` 两个主题入口
- [ ] 接入现有 Header / Footer / Theme
- [ ] 移动端保持与主站一致的阅读体验
- [ ] 不破坏原 Blog / Docs 路由

---

## 11. 明确不做

本阶段不做：

- 独立后台
- 学习账户系统
- 阅读进度云同步
- 打卡
- 积分
- 课程购买
- 复杂搜索
- 全新设计 token
- 独立主题系统
- 大规模迁移所有旧文章

---

## 12. 验收标准

设计层：

- 页面第一眼不像课程平台或 SaaS Dashboard
- 与 tomz.io 主站属于同一视觉体系
- 智能体与读经虽然题材不同，但放在同一「研习」空间不违和
- 用户能在 5 秒内理解“这里是持续学习路径，而不是普通文章分类”

信息架构层：

- `/learning` 成为唯一一级入口
- `/books` 不再形成另一套竞争体系
- 每条路径能展示当前进度与最近内容
- 内容不需要为了 Blog / Learning 双重归属复制两份

工程层：

- 不破坏现有 Markdown / MiraDocs 解析能力
- 不破坏现有静态生成与 GitHub Pages / Cloudflare 构建
- 不在组件中维护会迅速过时的“诗篇 04”“第 08 节”等硬编码事实
