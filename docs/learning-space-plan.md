# Learning Space 设计与信息架构方案

## 1. 定位

「研习」是 tomz.io 中承载长期学习、连续阅读与实践过程的一级内容空间。

它解决的不是“文章放在哪个分类”，而是另一个问题：

> 一条长期学习路径现在走到哪里，最近又发生了什么。

当前首批路径：

- 一起学智能体
- 读经札记

未来可以继续增加设计研究、产品研究或其他长期专题，但 V1 不为未来的数量提前制造复杂框架。

---

## 2. 核心模型

```text
长期主题
  ↓
连续路径
  ↓
当前进度
  ↓
最近记录
  ↓
继续阅读 / 思考 / 实践
```

「研习」不是新的内容仓库。

现有文章仍然只有一份：

```text
一份 Markdown
  ├─ 时间维度 → Blog
  └─ 路径维度 → Learning
```

因此：

- 不复制文章
- 不迁移现有博客 URL
- 不改署名与发布时间
- 不维护第二套文章目录

---

## 3. 一级入口

正式入口只有：

```text
/learning
```

顶栏名称：

```text
研习
```

历史「书架」方案废弃，不再作为产品模型、设计隐喻或兼容入口继续维护。

具体要求：

- 不保留 `/books` 跳转层
- 不保留「书架」导航项
- 不保留旧书架说明页
- 不以“书架 / 书脊 / 一本本书”组织 V1 页面

如果旧 `/books` 地址无人使用，直接自然失效即可，不为实验阶段历史路径增加永久兼容成本。

---

## 4. 产品原则

### 4.1 不是课程平台

不要出现典型 LMS / 在线课堂感：

- 不做课程购买
- 不做打卡体系
- 不做完成率 KPI
- 不做强制教学步骤
- 不做后台 Dashboard 式功能卡片堆积

用户进入页面时应该感受到：

> 有几件事情正在被长期学习和记录。

而不是：

> 这里有几门课程等待完成。

### 4.2 不是知识库目录

研习首页不是 Docs 树状目录。

首页只需要清楚回答：

- 正在学什么
- 当前走到哪里
- 最近写了什么
- 这条路径为什么值得继续

### 4.3 保留过程感

研习记录允许存在：

- 理解变化
- 阶段性结论
- 尚未解决的问题
- 与 Mira 的讨论
- 实践后的修正

不把真实学习过程清洗成一本“标准教材”。

### 4.4 继承 tomz.io

研习必须继续使用主站已有：

- 字体变量
- 颜色 token
- 页面宽度与留白系统
- 亮 / 暗主题
- Claude / Apple / Supabase 主题能力
- 导航与 Footer

它是 tomz.io 的一个内容视图，不是另起一个产品。

## 5. V1 页面结构

`/learning` 采用纵向路径结构，不使用同权 Dashboard 卡片。

```text
研习
一些仍在继续的学习、阅读和实践。

────────────────────
01
AI / AGENT
一起学智能体

路径说明
当前进度
记录数量

最近写下
<最近文章标题>
<日期>

查看这条路上的全部记录 →

────────────────────
02
READING / BIBLE
读经札记

路径说明
当前读到
札记数量

最近写下
<最近文章标题>
<日期>

查看这条路上的全部记录 →
```

### 首页强调

- 路径标题
- 当前进度
- 最近文章
- 内容数量 / 范围
- 路径仍在继续的感觉

### 首页不强调

- 功能 icon
- 课程章节卡片
- 复杂进度条
- 多个 CTA
- hover 炫技
- SaaS 指标

---

## 6. 视觉方向

关键词：

- 安静
- 长期
- 编辑感
- 索引感
- 阅读感
- 仍然属于 tomz.io

可以轻量使用：

- 01 / 02 这样的路径编号
- 索引线
- 轻分隔线
- 当前阅读位置
- 小尺寸 Lucide 图标作为辅助识别

避免：

- 拟物书架
- 书脊阵列
- 课程封面墙
- 大圆角功能卡片
- 知识付费首页
- Notion 模板市场感

读经路径可使用 `BookOpen` 作为辅助图标，但它表达的是“阅读”，不是重新引入书架模型。

---

## 7. 数据来源

V1 直接聚合现有 Markdown。

当前映射：

```text
Blog group: 一起学智能体
  ↓
Learning path: agent

Blog group: 读经札记
  ↓
Learning path: bible
```

页面自动推导：

- 最新文章
- 当前最大 order
- 文章数量
- 日期
- 进度文案

禁止在 React 中手写类似：

```text
诗篇 04
第 08 节
```

这类会迅速过时的事实。

未来确实需要更细粒度语义时，再为 Markdown 增加 `learning`、`chapter` 等 frontmatter；V1 不要求为了架构漂亮而批量改历史文章。

---

## 8. 与 Blog 的关系

Blog 继续承担时间流：

> 最近写了什么。

Learning 承担路径流：

> 这件事情学到哪里。

V1 不新增 `/learning/agent`、`/learning/bible` 内容副本。

「查看这条路上的全部记录」直接进入现有 Blog 分类筛选：

```text
/blogs?category=一起学智能体
/blogs?category=读经札记
```

这样可以保持：

- 一份内容
- 一套正文页
- 一套 SEO / 静态生成
- 两种浏览方式

## 10. 验收标准

### 设计

- 第一眼不像课程平台或 SaaS Dashboard
- 不出现旧书架式拟物 / 收藏模型
- 与 tomz.io 主站属于同一视觉体系
- 智能体与读经放在同一空间不违和
- 5 秒内能理解这里展示的是“持续路径”

### 信息架构

- `/learning` 是唯一研习一级入口
- 不再存在竞争性的 `/books` 内容体系
- 每条路径能展示真实当前进度与最近内容
- Blog 与 Learning 不复制正文

### 工程

- 不破坏 MiraDocs Markdown 解析
- 不破坏 Blog / Docs 原路由
- Root 与 GitHub Pages 构建通过
- 静态导航与客户端导航都只显示「研习」
- 代码中不残留为旧书架实验服务的跳转层
