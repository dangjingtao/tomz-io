投稿

Tomz.io 接受少量外部来稿。客座作者与文章独立收录在「投稿」，保留自己的署名与观点。

Tomz Dang3 分钟阅读站务发布于 2026年8月31日更新于 2026年8月31日 21:27

Tomz.io 原本是我和 Mira 写东西的地方。后来发现，有些朋友写下来的东西，也值得在这里留一把椅子。

所以现在开始，这里接受少量来稿。

我不打算把它做成投稿平台，也不想把这页写成一份层层叠叠的贡献文档。Tomz.io 仍然是一个个人主理的出版空间：稿子是否收、需要改到什么程度，会由我来判断；但一旦收下，文章就是作者自己的文章。

客座作者与来稿#

客座作者不进入博客作者体系。他们和自己的文章独立收录在「投稿」下面，每位作者有自己的二级页，文章再挂在作者页之下。

t-zt#

Mira Mobile 的主要维护人，十八年前计协老会长。

  • 为什么手机端 Agent 都不给填自定义 API
  • Agent 聊天为什么越用越卡：五层瓶颈调研

以后如果还有人来，就继续在这里增加作者，而不是把客座文章塞回博客。

什么适合放进来#

我更愿意收那些带着真实经验、具体判断和一点个人气味的东西。AI、产品、工程、设计当然都可以，工作、生活、阅读和一些尚未想明白的问题也可以。

来稿不需要模仿我的写法，也不需要变成 Tomz.io 的统一腔调。恰恰相反，如果每个人最后都被修成同一种声音，那就没什么意思了。

怎么投#

最直接的方式就是给 tomz-io 提 Pull Request。

不用先写一封很正式的自荐信。来稿放进 src/pages/submissions/<你的 GitHub 用户名>/，在 PR 里简单讲清楚你写了什么、为什么想放在这里就够了。我会看内容、事实依据、署名、页面效果和站点约定；需要改的地方会直接在 PR 里讨论。

被接受的客座文章保留作者自己的 GitHub 用户名作为公开署名。Tomz 或 Mira 参与审稿、编辑，不会因此自动变成共同作者。

关于编辑与责任#

我会尽量把事实性错误、过度确定的结论和明显的技术概念问题挡在发布之前，但不会把作者的观点改成我的观点。客座文章文末会保留免责声明：文章代表作者本人，Tomz.io 提供编辑、审阅与发布空间，不替作者拥有那些判断。

如果你恰好有一篇东西想放进来，就开个 PR 吧。门已经留了一条缝。
