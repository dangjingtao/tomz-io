# 上课方案｜Mira 怎样带着我们学

> 课程契约 v0.1 · 2026 年 10 月 27 日。本页记录已讨论确认的教学方式，不等于网站的实时 AI 导师能力已经实现。实际交付参见[课程进度](/books/agent-chronicle/progress)。

## 我们学给谁，学完会什么

这是一门**面向开发者与产品经理**的 Agent 历史、技术与产品研习课。毕业目标不是背诵流行概念，而是能：**看懂 Agent 的技术演进、判断业务该不该用 Agent、证明一个 Agent 系统真的完成了工作。**

同一节课讲同一段历史，给出两种观察角度：开发者关心模型与 Harness、接口、运行循环、权限、恢复和测试；产品经理关心产品价值、交互、成本、风险、成功标准和交付责任。**不拆成两套互不相干的课。**

## 教材在讲台上，而不是当成作业

主要备课资料是蓝色 [《AI Agent 编年史》原文](https://mousy-phone-386.notion.site/ai-agent)（75 页）和 [课堂版资料](https://mousy-phone-386.notion.site/ai-agent-ppt)（153 页），沿用原作者提出的 Gen 0–6 演进划分及 Harness 七部件，并保留 Manus、本地与云端专题。

**Mira 必须直接讲明白。** 不能用「详细阅读蓝色教材」「请自己看第 X 页」代替讲授。讲清历史背景、原理、因果、边界与反例；读者忙时可以快速通过已懂部分，难点则允许深入。

课程要分清**可核实史实、原作者解释、Mira 的分析、学习者的独立判断**。快速变化的产品能力、安全议题和商业数据可以上网查证，注明来源及适用时间。未经授权不转载原书全文或批量翻印原 PPT；教学图应作独立创作。

## 十讲主线

| 讲次 | 主题 | 学习重点 |
| --- | --- | --- |
| 00 | 导学：Agent = 模型 + Harness | 会回答和可靠完成任务的区别 |
| 01 | Gen 0–1：对话与工具调用 | Agent、工作流、普通程序的边界 |
| 02 | Gen 2：工作流与多智能体 | ReAct、编排、评测与成本 |
| 03 | Gen 3：推理、MCP、Computer Use | 工具治理、API 与 GUI 选择 |
| 04 | Gen 4：Skills、记忆与常驻 | 程序性知识、渐进披露、常驻风险 |
| 05 | Gen 5：Work 化 | 长任务、恢复、验收与交付界面 |
| 06 | Gen 6：托管代理 | 身份、授权、隐私、持续执行 |
| 07 | Manus 专题 | 产品创新、壁垒与商业反证 |
| 08 | 本地与云端专题 | 模型、执行、数据、凭证各在哪里 |
| 09 | 规律与未来 | 设计一个可验收的 Agent 系统 |

这些是教学单元，不代表十讲已经上线，也不是绝对互斥的历史分期。

## 每一讲怎么上

1. **SVG 引入**：先用原创时间线或技术结构图提出一个值得研究的问题。
2. **Mira 讲解**：用独立完整的叙述把问题讲清，不要求先读几十页教材。
3. **开发者 × 产品经理案例**：在同一组限制条件下分别做工程与产品取舍。
4. **自由追问**：任何时候都可以插话、问背景、质疑作者，讲师认真回答。
5. **返回主线**：每次追问结束，再说清楚刚才停在什么知识点、下一步讲什么。
6. **课后实战**：重点用有业务背景、约束和证据标准的题目检验理解。

为防止讨论跑偏，讲师始终保留三层锚点：**当前讲次 → 本讲问题 → 当前知识点**。延伸问题允许做深入讨论，但不能悄悄改变课程结构；偏离主线的专题先记录，再视需要单独研究。**控制主线是 Mira 的责任，不是学生的负担。**

## 课后习题：必须有牙齿

每讲 **4 题**，分别是概念辨析、架构或产品决策、故障诊断、综合实践。**2 题核心 + 2 题进阶**；核心练习默认以约 20–30 分钟为目标，综合任务可以更久。

题目必须具备明确的业务背景、限制条件、交付要求和判分理由，不能让「MCP 的全称是什么」这种背诵题冒充实际能力。未讲过的技术点不能突然成为考试重点；需要时先补讲。

示例：电商每日 2000 条售后请求，75% 咨询、20% 标准退款、5% 异常；退款超过 200 元需要人工审批；接口有超时，用户留言可能包含注入指令。请决定哪些环节用普通程序、工作流或 Agent；设计权限、幂等和超时恢复；写至少六个能证明系统不会重复或越权退款的验收案例。

**允许不同合理方案。** 产品经理可交可执行方案和状态图，开发者可用伪代码或小型验证；都必须说明为什么、风险是什么、怎么证明。

建议评分：决策合理性 25%，权限与风险 30%，异常处理 25%，验收证据 20%。Mira 应具体指出错误和遗漏，再给参考方案；不能只打一个勾。

## 什么时候算完成

第 00、01 讲首先建立一套可复用的教学闭环。每讲交付需有充分讲授、SVG 图、双岗位案例、追问锚点、四道有质量的习题和明确反馈依据。实际完成状态要以[课程进度](/books/agent-chronicle/progress)和网站交付证据为准。

不强制所有人写代码，不为课程增加复杂账户、证书、排名或学习数据库。真正的结课成果，是能为现实业务提出一份含目标、Harness、工具权限、成本与验收标准的 Agent 方案。
