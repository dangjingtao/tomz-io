# 为什么与 AI Agent 共事反而更累？

**原作者：Constantin Gonzalez**  
**原文：[Why working with AI agents is so tiring (and what to do about it)](https://constantin.glez.de/ai-agent-fatigue/)**  
**原文发表：2026 年 7 月 16 日**

Constantin 在慕尼黑的一个共享办公空间待了五小时。他让 AI Agent 分别帮助自己写博客、为开源项目贡献代码，以及修改网站的数据分析功能。每个 Agent 工作时，他就去审查另一个项目的成果，交代下一步任务。

事情进展很快。回家以后，他却感到一种熟悉的疲惫：像连续参加了一天工作面试，脑袋还在嗡嗡作响。

他借用餐厅厨房解释这种工作。人是主厨，Agent 是各自负责一道工序的厨师。真正的厨房里有订单架，没完成的菜、谁在做什么，都挂在外面。一个人同时开着几个 Agent，却常常把全部进度记在脑子里。

更麻烦的是，Agent 接走了相对轻松的部分：查资料、打草稿、写例行代码。留下给人的，是检查、比较、批准、纠错。这些工作往往更难，也更难停下来。

## 他怎样重新安排工作

Constantin 没有主张停止使用 Agent。他尝试把任务交接写得更清楚，让未完成事项留在纸面和看板上，而不是一直悬在脑子里；限制同时推进的任务数；把短暂休息安排在提交委托之后，而不是每隔几分钟就去查看 Agent 是否完成。

这些办法听上去不像什么先进技术。它们恰恰来自人类早就熟悉的工作组织经验：书面交接、在制品限制、可预期的休息。

文章里还有一个很好的细节：他提到母亲过去喜欢用俄罗斯方块一类电子游戏放松，如今自己也会在一天结束后玩《塞尔达传说》。一场关于 AI 生产力的讨论，最后落到了人怎样恢复注意力。

## 注意力没有随 Agent 增加

AI 让等待时间缩短，但没有让人类的注意力变成无限资源。

一个 Agent 在后台运行时，另一个任务当然可以开始；这不表示人必须把所有空档都填满。也许以后评价 AI 工具，还要看看它是否帮助用户交代清楚工作、回顾决策、放心离开，而不只是看它能同时启动多少个任务。

原文对“主厨”与“订单架”的比喻讲得更完整，也引述了其他开发者对 Agent 疲劳的不同感受。值得去读原文。
