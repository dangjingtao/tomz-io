# tomz.io 首页产品访谈纪要

日期：2026-08-19

状态：访谈阶段记录。本文只记录已经确认的诉求、约束、设计建议与待确认事项，不代表最终首页文案或视觉方案。

## 1. 首页希望传达的核心印象

访客第一次进入 tomz.io 后，希望记住两件事：

- 他对 AI、产品、人本身都很好奇。
- 他不是专家，但一直认真留下思考。

这里的重点不是建立“权威专家”形象，而是呈现持续的好奇、实践和思考。

## 2. 主要访问者

首页需要同时照顾以下几类人：

- 做 AI / 产品的人
- 独立开发者
- 设计师
- 认识 Tomz 的朋友、同事
- 未来可能的合作伙伴
- 单纯喜欢阅读个人写作的人

因此首页不能只做成作品集，也不能只做成传统博客首页。

## 3. 时间重心

首页需要同时呈现“现在的 Tomz”和“长期的 Tomz”。

已确认的优先级：

- 现在与长期大致各占一半
- 首页优先展示“最近发生的事”

目标是让访问者感受到：这个人此刻仍在持续做事、思考和写作，而不是只看到一份静态履历。

## 4. 首页核心内容顺序

首屏之后的主要内容优先级已确认：

1. 最近在做什么
2. 代表项目
3. 最近写了什么

即：先看到当前状态，再看到长期实践，最后进入文字内容。

## 5. 身份表达

首页需要保留一点简历 / 身份说明功能。这不是最喜欢的表达方式，但属于现实需求，尤其需要兼顾同事、合作伙伴和第一次认识 Tomz 的访问者。

目前确认公开的身份只有：

- 独立开发者
- 产品设计师

AI 暂不作为职业头衔本身，而更适合作为长期关注和正在实践的主题出现。

## 6. 首屏表达风格

首屏倾向采用干净、直接的自我介绍方式，而不是文学化表达或刻意强调观点。

方向示例：

> 我是 Tomz，一名独立开发者和产品设计师。这里记录我正在做的产品，以及关于 AI、产品和人的一些思考。

以上只是访谈阶段用于确认语气的示例，不是最终定稿。

## 7. 当前项目判断

### UIChat Mira

- 正式名称：UIChat Mira
- 明确属于可以在首页重点出现的项目
- 后续需要进一步确认它在“最近在做”和“代表项目”中的具体呈现方式

### Com Design

当前判断尚未稳定。

已有认识：

- 它可能逐渐成为一种“一人身兼多职”的工作系统 / 方法体系
- 但当前产品气质、边界和完成度都还没有完全确认
- 是否应作为首页代表项目，目前不做结论

因此第一版首页规划中，不应把 Com Design 当作已经确定的首页核心项目。

## 8. “最近在做”的自动生成方向

已确认首页的“最近在做”不以人工维护为主，而是根据最近活动自动生成。

产品语义不是直接展示 GitHub commit / activity feed，而是把底层活动归纳成访问者能理解的“最近在做什么”。

当前确认的生成策略：

1. **AI 总结为主路径。** AI 根据已经确定的近期事实，生成简短、自然的当前状态摘要。
2. **非 AI 机制作为兜底。** 当 AI 调用失败、结果不可用或摘要尚未生成时，使用规则 / 模板从已有事实生成可展示内容，首页不能因此出现空块。
3. **事实与总结分离。** AI 负责表达和归纳，不应自行发明项目状态、进展或活动事实。
4. **避免退化成 commit 流。** 单次提交、修 typo、CI 更新等低语义活动不应直接成为首页“最近在做”的内容。

### 公司工作是否可以进入“最近在做”

已确认：**可以。**

约束与偏好：

- 公司工作不需要被个人站原则性排除，只要它确实代表 Tomz 最近在做的事情，就可以成为候选活动。
- **优先脱敏。** 展示重点应放在“正在解决什么问题 / 做什么类型的工作”，而不是突出公司名、内部项目名、客户名或其他没有必要公开的组织信息。
- 脱敏是偏好而不是硬阻塞；如果某条内容难以自然脱敏，不因此强制删除整条活动。
- 首页不应把公司工作包装成替雇主做宣传的内容，仍然以 Tomz 的实践和判断为叙事中心。

### V1 数据源建议（待验证假设）

在尚未确认更多数据源之前，当前建议先收敛为：

- GitHub 活动：用于识别最近真正活跃的项目和工作，但需要过滤 CI、依赖更新、纯维护提交等低语义噪声。
- tomz.io 内容：最近发布的文章、项目页及持续出现的主题。
- 少量人工项目状态：例如 `active / paused / hidden`，作为自动判断的边界控制。

暂不把 Mira 私人对话、日历、Notion 或其他工作任务系统作为 V1 必需信号源。

以上数据源方案仍属于设计建议，不视为用户已经确认的最终技术需求。

## 9. 首页的产品角色

根据本轮访谈，首页首先应该是一个“人的入口”，而不是：

- SaaS 产品 Landing Page
- 单纯的技术博客首页
- 纯作品集
- 完整履历页

它需要很快回答：

- Tomz 是谁
- Tomz 最近在做什么
- Tomz 长期做过什么
- Tomz 最近在想和写什么

同时保留继续深入 About、项目、文章等内容的入口。

## 10. 已确认的产品原则

1. **以人作为信息架构中心。** 项目、文章和主题都围绕 Tomz 的持续实践展开。
2. **最近发生的事优先。** 首页不是档案馆首页，需要体现当前状态。
3. **项目先于文章。** 首页内容顺序为“最近在做 → 代表项目 → 最近写了”。
4. **保持克制。** 首页需要一点简历作用，但不应变成招聘式个人主页。
5. **不塑造专家权威。** “认真留下思考”比“证明自己懂很多”更重要。
6. **AI 是关注领域，不是强行附着的职业标签。**
7. **动态信息优先自动生成。** 首页应尽量从真实活动中产生“现在”的状态，而不是增加日常手工维护负担。
8. **AI 主总结，确定性机制兜底。** 智能表达不能成为首页可靠性的单点依赖。
9. **工作与个人实践可以共存。** 公司工作可以进入首页动态，但默认尽量脱敏，并以个人实践而非组织宣传为叙事中心。

## 11. 尚未确认

以下内容仍需要后续访谈或设计阶段决定：

- “最近在做什么”最终展示多少项，以及活动信号、时间窗口和排序规则
- V1 是否正式采用“GitHub + tomz.io + 少量人工项目状态”作为信号源
- 公司工作脱敏的具体规则，以及哪些信息应硬性排除
- AI 摘要的触发时机、缓存与更新频率
- UIChat Mira 的首页项目文案和信息层级
- tomz.io 本身是否作为一个持续建设中的项目展示
- Com Design 最终是否进入代表项目
- 首页是否使用个人头像或其他个人视觉元素
- About 页面需要公开到什么程度的履历信息
- 首页完整文案
- 首页视觉方向与模块布局
- 各内容模块与现有 Markdown 内容结构之间的具体映射
